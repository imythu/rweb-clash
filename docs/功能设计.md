# R-Clash 功能设计

本文档根据现有前端 UI 反推产品功能、后端能力边界和主要数据模型。当前阶段只描述功能设计，不约束具体 Rust 实现细节。

## 1. 产品定位

R-Clash 是一个面向普通用户和进阶用户的 Clash/Mihomo 客户端。设计目标不是复刻传统配置文件编辑器，而是把代理客户端抽象成几个可理解的工作台：

- 总览：控制系统代理、TUN、运行模式，查看实时状态。
- 订阅管理：管理资源提供者，做节点清洗和订阅同步。
- 分组管理：管理代理组和节点选择，支持按语义规则创建自定义分组。
- 路由管理：管理分流规则、规则集和路由测试。
- 运行日志：观察内核运行日志，并从日志快速生成规则。
- 系统设置：提供基础预设和专家级内核参数配置。

后端需要把 Clash/Mihomo 的底层能力包装成稳定 API，并负责把用户操作持久化、转换为运行时配置、应用到内核。

## 2. 打包与运行模式

### 2.1 Linux 单可执行文件

Linux 下先构建 `web/` 前端，再由 Rust 二进制提供：

- HTTP API。
- 静态资源服务。
- Mihomo 进程生命周期管理。
- 本地配置、订阅、规则和运行状态持久化。

### 2.2 Tauri 应用

Windows、macOS 和 Android 使用 Tauri 打包：

- 前端仍复用 `web/`。
- Tauri 入口复用共享库中的业务能力。
- 桌面和移动端可按平台差异处理系统代理、TUN 权限、路径和启动方式。

## 3. 页面级功能设计

## 3.1 总览

总览页是运行控制中心，要求后端提供低延迟、可轮询的状态接口。

### 主要功能

- 系统代理开关。
- TUN 模式开关。
- 运行模式切换：`rule`、`global`、`direct`。
- 实时上传和下载速度展示。
- 活跃连接数展示。
- 核心负载展示。
- 出口 IP、云厂商、国家/地区画像展示。
- 侧边栏系统状态展示。

### 后端能力

- 读取和更新核心配置。
- 应用模式切换到 Mihomo 运行时。
- 开启或关闭系统代理。
- 开启或关闭 TUN。
- 获取实时流量。
- 获取活跃连接。
- 获取内核运行状态和版本。
- 查询出口 IP 信息。

### 相关接口

- `GET /api/configs`
- `PATCH /api/configs`
- `GET /api/traffic`
- `GET /api/connections`
- `GET /api/system/status`
- `GET /api/system/egress`

## 3.2 订阅管理

订阅管理页把每个订阅视为一个“资源提供者”，重点不是简单保存 URL，而是导入、同步、清洗、统计和继承全局准则。

### 主要功能

- 订阅资源列表。
- 添加订阅：名称、URL、同步频率、是否继承全局精选准则。
- 编辑订阅基础信息。
- 删除订阅。
- 复制订阅 URL。
- 展示订阅状态：在线、失效、同步中。
- 展示流量用量和总量。
- 展示到期时间。
- 展示节点数量。
- 展示订阅解析后的节点类型构成。
- 配置订阅级精选规则。
- 配置全局精选准则。

### 订阅精选规则

规则用于在订阅入池前过滤节点。UI 支持：

- 动作：引入、剔除。
- 匹配类型：包含、不包含、正则匹配。
- 匹配字段：当前 UI 主要针对节点名。
- 全局规则可被订阅继承。

### 后端能力

- 保存订阅元数据。
- 下载订阅内容。
- 解析 Clash/Mihomo 配置。
- 读取订阅流量信息，例如 `subscription-userinfo`。
- 根据规则清洗节点。
- 合并全局规则和订阅级规则。
- 记录同步状态、错误信息和最近更新时间。
- 按同步频率自动刷新。
- 将刷新后的节点资产写入可供分组和规则使用的节点池。

### 相关接口

- `GET /api/subscriptions`
- `POST /api/subscriptions`
- `PATCH /api/subscriptions/{id}`
- `DELETE /api/subscriptions/{id}`
- `POST /api/subscriptions/{id}/refresh`
- `GET /api/subscription-rules/global`
- `PUT /api/subscription-rules/global`

## 3.3 分组管理

分组管理页是代理出口调度中心。它同时展示订阅内置分组和用户自定义分组。

### 主要功能

- 代理组列表。
- 节点列表。
- 搜索分组。
- 搜索节点。
- 查看分组类型：`select`、`url-test`、`fallback`、`load-balance`。
- 查看当前出口。
- 切换 `select` 分组选中节点。
- 分组测速。
- 单节点测速。
- 新建自定义分组。
- 编辑自定义分组。
- 订阅托管分组只读，不允许编辑。

### 自定义分组规则

新建和编辑分组时，UI 提供语义积木式过滤器：

- 分组名称。
- 分组类型：手动选择、自动测速、故障转移、负载均衡。
- 过滤动作：引入、剔除。
- 过滤维度：节点名、国家/地区、协议、延迟、状态、订阅源。
- 操作符：包含、等于、正则、小于、状态匹配。
- 实时预览命中节点。

### 后端能力

- 从运行配置和订阅解析结果生成代理拓扑。
- 区分订阅托管分组和用户自定义分组。
- 保存用户自定义分组定义。
- 按语义过滤器计算分组节点。
- 将自定义分组写入运行时 Clash 配置。
- 切换代理组出口。
- 调用 Mihomo controller 进行延迟测试。
- 返回节点所属订阅、协议、地区、延迟等增强字段。

### 相关接口

- `GET /api/proxies`
- `POST /api/proxies`
- `PUT /api/proxies/{group}`
- `DELETE /api/proxies/{group}`
- `POST /api/proxies/{group}/test`
- `POST /api/nodes/test`

## 3.4 路由管理

路由管理页是分流规则工作台，负责维护规则顺序、规则集和沙盒测试。

### 主要功能

- 展示当前路由规则列表。
- 搜索规则。
- 新增规则。
- 编辑规则。
- 删除规则。
- 刷新规则和规则集。
- 规则集库管理。
- 规则分流沙盒测试。

### 路由规则

UI 支持的规则类型：

- `RULE-SET`
- `DOMAIN-SUFFIX`
- `DOMAIN`
- `DOMAIN-KEYWORD`
- `IP-CIDR`
- `GEOIP`
- `MATCH`

规则动作支持：

- `DIRECT`
- `REJECT`
- 代理组。
- 具体节点。

### 规则集库

规则集库支持：

- 添加规则集订阅：名称、URL、同步间隔。
- 查看规则数量。
- 查看最近更新时间。
- 手动刷新规则集。
- 删除规则集。

### 追踪实验室

用户输入域名或 IP 后，后端返回：

- 命中的规则。
- 目标策略。
- 最终出口节点。

### 后端能力

- 保存用户自定义规则并维护顺序。
- 保存规则集订阅。
- 下载和解析规则集。
- 将用户规则、规则集、订阅生成规则合并为运行时规则。
- 支持规则测试，不必真实建立连接。
- 规则变更后热更新 Mihomo 配置。

### 相关接口

- `GET /api/rules`
- `POST /api/rules`
- `PUT /api/rules/{id}`
- `DELETE /api/rules/{id}`
- `POST /api/rules/test`
- `GET /api/rule-sets`
- `POST /api/rule-sets`
- `POST /api/rule-sets/{id}/refresh`
- `DELETE /api/rule-sets/{id}`

## 3.5 运行日志

运行日志页不仅展示日志，还支持从连接日志中快速创建规则。

### 主要功能

- 拉取运行日志。
- 按级别过滤：全部、info、warning、error。
- 按关键字搜索日志。
- 自动滚动到底部。
- 导出全部日志。
- 清空日志。
- 从连接日志解析目标域名、命中规则和当前策略。
- 打开“规则快捷实验室”。
- 根据日志快速创建高优先级路由规则。

### 日志快捷规则

从日志创建规则时，UI 支持：

- 匹配范围：域名后缀、精确域名、关键词。
- 部署出口：`DIRECT`、`REJECT` 或代理组。
- 自动生成规则描述。

### 后端能力

- 订阅 Mihomo 日志流。
- 缓存最近日志。
- 提供日志查询和过滤。
- 提供日志导出。
- 清空本地日志缓存。
- 入库时持久化解析出的目标域名；命中规则和策略可从日志原文按需解析。
- 支持从日志创建规则，并将该规则置于高优先级。

### 相关接口

- `GET /api/logs`
- `DELETE /api/logs`
- `GET /api/logs/export`
- `POST /api/rules`

后续可补充：

- `GET /api/logs/stream` 用 SSE 替代轮询。

## 3.6 系统设置

系统设置页分为基础模式和专家模式。基础模式提供用户可理解的预设，专家模式直接暴露核心配置。

### 基础模式

核心预设：

- 极速冲浪模式：`dns_mode = fake-ip`，启用 `tcp_concurrent` 和 `unified_delay`。
- 极致兼容模式：`dns_mode = redir-host`，关闭 `tcp_concurrent`。

功能扩展：

- 全屋设备共享：`allow_lan`。
- 节点选择记忆：`store_selected`。

UI 会检测专家模式修改导致的预设偏离，并提示用户恢复推荐值。

### 专家模式

专家模式支持：

- 允许局域网。
- IPv6。
- 日志等级。
- 内核 DNS。
- DNS 模式。
- TCP 并发。
- 体感延迟。
- 混合端口。
- 节点记忆。
- 保存全部。

当前 UI 还定义了但未完整展示的字段：

- `external_controller`
- `external_controller_enabled`
- `secret`

### 后端能力

- 读取完整系统配置。
- 局部更新配置。
- 校验端口、地址、密钥和枚举值。
- 将设置转换为 Clash/Mihomo 配置。
- 判断哪些配置可以热更新，哪些需要重启内核。
- 提供 DNS 缓存清理。

### 相关接口

- `GET /api/configs`
- `PATCH /api/configs`
- `POST /api/dns/flush`

## 4. 核心后端模块

按照当前项目骨架，建议只保留三块：

- `crates/rweb-clash`：共享库，承载业务能力。
- `crates/rweb-clash-bin`：Linux/HTTP 二进制入口。
- `apps/desktop`：Tauri 应用入口。

共享库内部可以用模块组织，不必拆成多个 crate：

- `config`：系统配置、预设、运行时配置生成。
- `core`：Mihomo 进程管理、controller 客户端。
- `subscription`：订阅下载、解析、同步、流量信息。
- `asset`：节点资产池、订阅来源、协议和地区信息。
- `proxy`：代理组、自定义分组、测速、节点选择。
- `rule`：路由规则、规则集、规则测试。
- `log`：日志流、日志缓存、日志解析。
- `traffic`：流量和连接统计。
- `storage`：本地持久化。
- `platform`：系统代理、TUN、路径和权限差异。

## 6. 配置生成流程

后端需要把用户配置转换为 Mihomo 运行时配置：

1. 读取系统配置。
2. 同步订阅并解析节点。
3. 应用全局精选准则。
4. 应用订阅级精选规则。
5. 建立统一出站对象池 `proxy_items`，节点、订阅托管分组、自定义分组共用同一名称空间。
6. 保留订阅托管分组。
7. 计算用户自定义分组。
8. 合并用户规则和规则集。
9. 写出运行时 Clash/Mihomo YAML。
10. 启动或热更新 Mihomo。

配置冲突处理原则：

- 用户自定义规则优先级高于订阅内置规则。
- 日志快捷规则默认放在用户规则顶部。
- 订阅托管分组只读，避免刷新后被覆盖。
- 自定义分组引用 `proxy_items`，订阅刷新后重新计算。
- 生成 YAML 前校验分组成员、路由策略引用、分组循环引用。
- 若路由规则（`routing_rules.policy`）引用的策略目标已不存在（例如订阅被删导致分组或节点消失），则生成配置时系统应将其默认降级为 `DIRECT` 或 `REJECT`，避免内核启动失败。
- 规则和分组变更后优先热更新，热更新失败再重启内核。

## 7. 后端状态与任务

后端需要管理以下后台任务：

- 订阅自动刷新任务。
- 规则集自动刷新任务。
- 流量统计采集任务。
- 连接列表采集任务。
- 日志订阅和缓存任务。
- 节点测速任务。
- 核心健康检查任务。

任务状态通过对应业务表状态和日志体现，不单独维护任务运行表。

## 8. 错误处理

统一错误响应：

```json
{
  "error": {
    "code": "subscription_invalid_url",
    "message": "订阅地址格式不正确",
    "trace_id": "..."
  }
}
```

建议错误分类：

- `config_invalid`
- `core_not_running`
- `core_start_failed`
- `controller_unreachable`
- `subscription_invalid_url`
- `subscription_fetch_failed`
- `subscription_parse_failed`
- `rule_invalid`
- `ruleset_fetch_failed`
- `permission_denied`
- `platform_unsupported`

## 9. 实现范围

本文档描述的功能均属于目标实现范围，不再分阶段裁剪。

运行时配置只维护一个合成产物 `runtime.yaml`。
