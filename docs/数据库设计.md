# R-Clash 数据库设计

本文档根据现有前端 UI 和功能设计推导后端持久化结构。目标是支持本地客户端场景，优先选择 SQLite。

## 1. 设计原则

- 本地优先：用户配置、订阅、规则、规则集文件、日志和流量采样保存在本机。
- 用户配置优先：用户自定义规则、分组和设置必须稳定持久化。
- 运行时分离：数据库保存用户意图和缓存结果，实际 Mihomo YAML 由后端生成。
- SQLite 开启外键，使用级联删除清理从属缓存。
- 规则集按文件保存：数据库只保存规则集文件路径和元数据，不逐条保存规则集内容。
- 节点、代理组、自定义节点都写入 `proxy_items`，用 `kind` 区分类型，`name` 是 Mihomo 全局出站名称。
- 默认使用物理删除，避免软删除导致子表可见性判断遗漏。

## 2. 表清单

| 表名 | 用途 |
| --- | --- |
| `app_settings` | 通用配置项，每行一个配置 |
| `subscriptions` | 订阅资源 |
| `subscription_rules` | 订阅级节点精选规则 |
| `global_filter_rules` | 全局精选准则 |
| `proxy_items` | 出站对象，统一保存节点、代理组和自定义节点 |
| `proxy_group_filters` | 自定义分组过滤规则 |
| `proxy_group_members` | 分组成员关系缓存 |
| `routing_rules` | 用户路由规则 |
| `rule_sets` | 规则集文件订阅和本地文件元数据 |
| `traffic_snapshots` | 流量聚合采样缓存 |
| `log_entries` | 运行日志缓存 |

## 3. 通用字段约定

- `proxy_items.name` 是 Mihomo 出站全局名称，节点和代理组共用同一个命名空间。
- 时间统一使用 UTC ISO-8601 字符串。
- 布尔字段在 SQLite 中使用 `INTEGER NOT NULL DEFAULT 0/1`。
- 所有间隔统一使用秒，字段名统一为 `interval_seconds`。
- `position` 表示用户可见顺序，越小越靠前。初始写入建议使用步长，例如 1024、2048，拖拽时尽量只更新被移动项。
- `enabled` 表示保留但暂不启用。
- SQLite 连接必须执行 `PRAGMA foreign_keys = ON;`。

## 4. 表结构

## 4.1 app_settings

保存通用配置项。每行一个配置，全部按字符串保存，由使用方自行解析。

```sql
CREATE TABLE app_settings (
  scope TEXT NOT NULL DEFAULT 'system',
  key TEXT NOT NULL,
  value TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  PRIMARY KEY (scope, key)
);

```

## 4.2 subscriptions

保存订阅资源提供者。

```sql
CREATE TABLE subscriptions (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  url TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'online',
  interval_seconds INTEGER NOT NULL DEFAULT 21600,
  inherit_global_rules INTEGER NOT NULL DEFAULT 1,
  upload_bytes INTEGER,
  download_bytes INTEGER,
  total_bytes INTEGER,
  expire_at TEXT,
  node_count INTEGER NOT NULL DEFAULT 0,
  sync_started_at TEXT,
  sync_finished_at TEXT,
  sync_duration_ms INTEGER,
  sync_error_count INTEGER NOT NULL DEFAULT 0,
  next_sync_at TEXT,
  last_update_at TEXT,
  last_error TEXT,
  raw_etag TEXT,
  raw_last_modified TEXT,
  raw_content_hash TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE INDEX idx_subscriptions_next_refresh ON subscriptions(next_sync_at);
```

## 4.3 global_filter_rules

保存全局节点精选准则。

```sql
CREATE TABLE global_filter_rules (
  id TEXT PRIMARY KEY,
  position INTEGER NOT NULL,
  action TEXT NOT NULL,
  match_type TEXT NOT NULL,
  pattern TEXT NOT NULL,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE INDEX idx_global_filter_rules_position ON global_filter_rules(position);
```

## 4.4 subscription_rules

保存订阅级节点精选规则。

```sql
CREATE TABLE subscription_rules (
  id TEXT PRIMARY KEY,
  subscription_id TEXT NOT NULL,
  position INTEGER NOT NULL,
  action TEXT NOT NULL,
  match_type TEXT NOT NULL,
  pattern TEXT NOT NULL,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (subscription_id) REFERENCES subscriptions(id) ON DELETE CASCADE
);

CREATE INDEX idx_subscription_rules_sub_position ON subscription_rules(subscription_id, position);
```

## 4.5 proxy_items

保存 Mihomo 出站对象。节点和代理组共享同一张表，`name` 是写入 Mihomo 配置的全局唯一名称。

```sql
CREATE TABLE proxy_items (
  name TEXT PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('node', 'group')),
  subscription_id TEXT,
  display_name TEXT NOT NULL,
  source TEXT NOT NULL,
  source_name TEXT,
  protocol TEXT,
  country TEXT,
  group_type TEXT,
  raw_json TEXT,
  content_hash TEXT,
  latency_ms INTEGER,
  last_test_at TEXT,
  alive INTEGER NOT NULL DEFAULT 1,
  filtered_out INTEGER NOT NULL DEFAULT 0,
  filter_reason TEXT,
  delay_ms INTEGER,
  tolerance_ms INTEGER,
  url TEXT,
  interval_seconds INTEGER,
  strategy_json TEXT NOT NULL DEFAULT '{}',
  position INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (subscription_id) REFERENCES subscriptions(id) ON DELETE CASCADE
);

CREATE INDEX idx_proxy_items_kind ON proxy_items(kind);
CREATE INDEX idx_proxy_items_subscription ON proxy_items(subscription_id);
CREATE INDEX idx_proxy_items_lookup ON proxy_items(kind, filtered_out, country, protocol);
CREATE INDEX idx_proxy_items_latency ON proxy_items(kind, alive, latency_ms);
CREATE INDEX idx_proxy_items_position ON proxy_items(kind, position);
```

说明：

- `kind`：`node` 或 `group`。
- `kind = 'node'` 时使用 `protocol`、`country`、`raw_json`、`latency_ms` 等节点字段。
- `kind = 'group'` 时使用 `group_type`、`delay_ms`、`url`、`interval_seconds`、`strategy_json`、`position` 等分组字段。
- 自定义节点同样写入本表，`subscription_id` 为空即可。

## 4.6 proxy_group_filters

保存自定义分组过滤规则。

```sql
CREATE TABLE proxy_group_filters (
  id TEXT PRIMARY KEY,
  group_name TEXT NOT NULL,
  position INTEGER NOT NULL,
  action TEXT NOT NULL,
  field TEXT NOT NULL,
  operator TEXT NOT NULL,
  value TEXT NOT NULL DEFAULT '',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (group_name) REFERENCES proxy_items(name) ON DELETE CASCADE
);

CREATE INDEX idx_proxy_group_filters_group_position ON proxy_group_filters(group_name, position);
```

## 4.7 proxy_group_members

保存分组成员关系缓存。成员按 Clash/Mihomo 原始名称保存。

```sql
CREATE TABLE proxy_group_members (
  group_name TEXT NOT NULL,
  member_name TEXT NOT NULL,
  position INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  PRIMARY KEY (group_name, member_name),
  FOREIGN KEY (group_name) REFERENCES proxy_items(name) ON DELETE CASCADE
);

CREATE INDEX idx_proxy_group_members_name ON proxy_group_members(member_name);
CREATE INDEX idx_proxy_group_members_position ON proxy_group_members(group_name, position);
```

## 4.8 routing_rules

保存用户路由规则。

```sql
CREATE TABLE routing_rules (
  id TEXT PRIMARY KEY,
  position INTEGER NOT NULL,
  rule_type TEXT NOT NULL,
  value TEXT NOT NULL,
  policy TEXT NOT NULL,
  source TEXT NOT NULL DEFAULT 'user',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE INDEX idx_routing_rules_active_position ON routing_rules(enabled, position);
CREATE INDEX idx_routing_rules_search ON routing_rules(rule_type, value, policy);
```

## 4.9 rule_sets

保存规则集文件订阅和本地文件元数据。规则集本体作为文件落盘。

```sql
CREATE TABLE rule_sets (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  url TEXT NOT NULL,
  behavior TEXT,
  format TEXT NOT NULL DEFAULT 'text',
  local_path TEXT,
  file_size_bytes INTEGER,
  interval_seconds INTEGER NOT NULL DEFAULT 86400,
  rule_count INTEGER NOT NULL DEFAULT 0,
  last_update_at TEXT,
  last_error TEXT,
  raw_etag TEXT,
  raw_last_modified TEXT,
  content_hash TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE UNIQUE INDEX idx_rule_sets_name ON rule_sets(name);
CREATE INDEX idx_rule_sets_refresh ON rule_sets(interval_seconds, last_update_at);
```

## 4.10 traffic_snapshots

保存流量聚合采样，用于后续曲线图。秒级实时流量只放内存环形缓存，不直接写入 SQLite。

```sql
CREATE TABLE traffic_snapshots (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  bucket_start INTEGER NOT NULL,
  bucket_seconds INTEGER NOT NULL,
  avg_upload_bps INTEGER NOT NULL,
  avg_download_bps INTEGER NOT NULL,
  max_upload_bps INTEGER NOT NULL,
  max_download_bps INTEGER NOT NULL,
  avg_active_connections INTEGER NOT NULL DEFAULT 0,
  max_active_connections INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);

CREATE UNIQUE INDEX idx_traffic_snapshots_bucket ON traffic_snapshots(bucket_start, bucket_seconds);
```

## 4.11 log_entries

保存运行日志缓存。

```sql
CREATE TABLE log_entries (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  time TEXT NOT NULL,
  level TEXT NOT NULL,
  payload TEXT NOT NULL,
  parsed_host TEXT,
  created_at TEXT NOT NULL
);

CREATE INDEX idx_log_entries_time ON log_entries(time);
CREATE INDEX idx_log_entries_level_time ON log_entries(level, time);
CREATE INDEX idx_log_entries_parsed_host ON log_entries(parsed_host);
```

## 5. 字段说明

字段含义以表结构命名为准：

- `subscription_id`：订阅 ID，子表通过外键级联清理。
- `group_name`：代理组名称，对应 `proxy_items.name` 且 `kind = 'group'`。
- `member_name`：写入 Mihomo 配置的成员名称。
- `position`：排序值，越小越靠前。
- `enabled`：是否启用。
- `raw_json`：节点原始配置 JSON。
- `content_hash`：内容哈希，用于判断变更。
- `local_path`：规则集本地文件路径。
- `latency_ms`：用于 `kind = 'node'` 时，保存单节点测速结果。
- `delay_ms`：用于 `kind = 'group'` 时，保存代理组展示或汇总测速结果。
- `tolerance_ms`：用于 `kind = 'group'` 且 `group_type = 'url-test'` 时，保存自动测速分组的容差参数。

## 6. 关系说明

- 一个订阅可以产生多个出站对象 `proxy_items`，包括节点和系统来源代理组。
- `proxy_items.name` 是 Mihomo 全局出站名称空间，天然防止节点、代理组、自定义节点重名。
- 一个自定义分组可以有多个过滤器 `proxy_group_filters`。
- 一个分组可以包含多个成员，成员按原始名称保存到 `proxy_group_members`。
- `proxy_group_filters.group_name` 和 `proxy_group_members.group_name` 的外键只能保证名称存在；保存前后端还必须校验对应 `proxy_items.kind = 'group'`。
- `proxy_group_members.member_name` 不使用外键，因为它可以引用节点、代理组或 Mihomo 保留名称；生成配置前由后端统一校验有效性，若发现孤儿引用（例如订阅被删导致节点消失）需要在生成时忽略并在业务层进行清理。
- 一个规则集 `rule_sets` 对应一个本地规则集文件。
- 用户路由规则 `routing_rules` 可以引用代理组名称、节点名称、`DIRECT` 或 `REJECT`。若引用的策略目标已不存在，应在生成配置时默认降级为 `DIRECT`。
- 日志 `log_entries` 用于排查问题和快捷创建规则。

## 7. 关键查询

## 7.1 配置读取

```sql
SELECT scope, key, value
FROM app_settings
ORDER BY scope, key;
```

```sql
UPDATE app_settings
SET value = ?, updated_at = ?
WHERE scope = ? AND key = ?;
```

## 7.2 订阅列表

```sql
SELECT *
FROM subscriptions
ORDER BY created_at DESC;
```

## 7.3 可用节点池

```sql
SELECT *
FROM proxy_items
WHERE kind = 'node' AND filtered_out = 0
ORDER BY subscription_id, display_name;
```

## 7.4 代理拓扑

```sql
SELECT *
FROM proxy_items
WHERE kind = 'group' AND enabled = 1
ORDER BY position, created_at;
```

```sql
SELECT *
FROM proxy_group_members
WHERE group_name = ?
ORDER BY position, member_name;
```

## 7.5 路由规则

```sql
SELECT *
FROM routing_rules
WHERE enabled = 1
ORDER BY position;
```

## 7.6 日志搜索

```sql
SELECT *
FROM log_entries
WHERE (? = 'all' OR level = ?)
  AND payload LIKE '%' || ? || '%'
ORDER BY time DESC
LIMIT ? OFFSET ?;
```

## 8. 迁移策略

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  applied_at TEXT NOT NULL
);
```

初始迁移建议：

1. 创建配置、订阅、节点、分组、规则、规则集、日志和流量采样表。
2. 插入 `app_settings` 默认配置项。

## 9. 清理策略

- `traffic_snapshots`：默认保留 24 小时。
- `log_entries`：默认保留最近 10000 条或 7 天。
- `proxy_items`：订阅刷新后按 `subscription_id` 重建或增量更新。
- `proxy_group_members`：订阅刷新、分组过滤规则变更或分组引用变化后重建。
- `rule_sets.local_path` 指向的文件：规则集刷新后按文件覆盖或原子替换。
